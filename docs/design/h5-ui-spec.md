# H5 UI 规格

- 状态：登录到入会流程已落地；会中移动端新版布局、抽屉和全屏交互已落地
- 范围：`H5` 浏览器端从登录到进入会议，以及会中移动端新版布局、抽屉和全屏交互
- 对应预览：
  - `docs/design/h5-auth-preview.html`
  - `docs/design/h5-room-preview.html`

## 1. 目标

- 登录到入会流程以 `web/src/App.tsx` 当前实现为准；会中移动端以 `docs/design/h5-room-preview.html` 作为后续实现依据。
- 继续沿用 `PC Web` 的深色舞台、`meeting` 字标、底部聚光灯、蓝色主按钮和玻璃感面板。
- `H5` 不是把 `PC` 页面等比压缩，而是基于同一视觉系统重排触控优先级、表单密度和会中工具布局。

## 2. 设备分档

### 手机主档

- 基准宽度：`390px` 左右竖屏。
- 交互原则：单列、拇指优先、底部操作区优先。
- 面板策略：`sheet` / 底部抽屉优先。

### iPad / 小屏平板档

- 基准宽度：`820px` 左右竖屏。
- 交互原则：保留 `H5` 壳层，但允许局部双列和右侧贴附面板。
- 面板策略：聊天默认隐藏，聊天和成员都从底部工具栏上方贴附弹出；更多和邀请保留底部贴附面板；底部工具栏仍保留会中主操作。

## 3. 全局角标

- 登录页、登录后入口、加入会议和入会预览左下角都要固定显示版本信息角标。
- 角标固定为 `3` 行，顺序不可擅自调整：
  - `version`
  - `commit`
  - `build time`
- 角标必须使用低对比灰色，不参与主要交互，不得抢占按钮层级，也不应成为页面视觉焦点。
- 会中页不显示版本信息角标，避免干扰舞台和工具栏区域。

## 4. 登录到入会流程

- `Web` 桌面端和 `H5` 移动端的登录、注册、登录后入口、预定会议、加入会议、密码确认和入会预览页都必须保持单页显示，不应依赖用户上下拖动才能看到底部按钮。
- 手机端高度不足时优先压缩主卡片内部密度，包括卡片内边距、表单间距、输入框高度、按钮高度和状态提示高度；不得通过缩小或移除顶部 `meeting` 字标与聚光灯来换取空间。
- 手机端关键主操作按钮必须在首屏可见，尤其是登录页的 `登录 / 加入会议`、加入会议页的 `验证会议号 / 返回`、入会预览页的 `进入会议 / 返回修改入会信息`。

### 页面 1：登录

- 顶部品牌区顺序：
  - `meeting`
  - 聚光灯
- 主卡片内容：
  - 登录方式标题
  - `使用验证码登录 > / 使用密码登录 >`
  - `没有账号？去注册 >`
  - 邮箱输入
  - 验证码输入或密码输入
  - `忘记密码`
  - `登录`
  - `微信快捷登录`
  - `加入会议`

不可擅自变更：

- `meeting` 字标和聚光灯必须保留在品牌区。
- 登录页不展示说明性副文案或品牌标签。
- `加入会议` 仍然需要在登录卡片内直接可达，不能藏入二级菜单。
- 微信登录在当前实现中是独立图标按钮，设计稿不得改成另一套主流程。

### 页面 2：注册

- 字段顺序：
  - 邮箱
  - 昵称
  - 验证码
- 主操作顺序：
  - `注册`
  - `加入会议`
- 次级入口：
  - `已有账号？去登录 >`

不可擅自变更：

- 注册完成后返回登录页重新登录的流程语义必须保留。

### 页面 3：登录后入口

- 卡片顺序：
  - `快速会议`
  - `预定会议`
- 卡片按钮顺序：
  - `快速会议`
  - `预定会议`
- 辅助入口：
  - `已有会议号？加入会议`
- 最近会议摘要：
  - 会议号
  - 主题
  - 时间
  - 是否需要密码

手机与 iPad 差异：

- 手机：能力卡纵向堆叠。
- iPad：能力卡允许双列并排。

不可擅自变更：

- 登录后入口仅保留卡片标题与操作按钮，不展示说明性副文案。
- `快速会议` 点击后直接进入会议房间，不再经过入会预览。

### 页面 4：预定会议

- 表单字段顺序：
  - `会议主题`
  - `会议时间`
  - `时区`
  - `会议密码（可选）`
- 底部按钮顺序：
  - `预定并进入预览`
  - `返回`

实现说明：

- 当前后端还没有真正的预约会议模型，本轮预定表单会创建可立即进入的会议，然后跳入会预览。

### 页面 5：加入会议

- 字段顺序：
  - `会议号`
  - `昵称`
- 会议号输入区形态：
  - 输入框
  - 右侧内嵌 `扫码` 按钮
- 入会偏好顺序：
  - `入会时希望开启摄像头`
  - `入会时希望开启麦克风`
- 底部按钮顺序：
  - `验证会议号`
  - `返回`

不可擅自变更：

- 会议号仍然使用公开 `9` 位数字并按 `3-3-3` 展示。
- 仍然是“先验证会议号，再决定是否弹出密码确认”；无需密码或密码确认成功后直接进入会议，不再进入入会预览。

### 页面 6：密码确认

- 手机端形态：固定悬浮窗 / 遮罩层中的卡片。
- iPad 端形态：同一层级的居中浮层。
- 信息顺序：
  - 已确认会议号
  - 标题 `请输入会议密码`
  - 密码输入框
  - `加入会议`
  - `返回`

### 页面 7：扫码加入会议

- 入口位置：加入会议页会议号输入框右侧。
- 弹层顺序：
  - 标题 `扫码加入会议`
  - 右上角关闭按钮
  - 状态说明
  - 实时扫码区或降级占位区
  - 状态文案
  - `拍照 / 选图识别二维码`
- 实时扫码区必须展示居中的取景框提示，引导用户把二维码放入框内；识别成功后立即关闭扫码层并回填信息。
- 小屏浏览器地址栏压缩可用高度时，弹层必须优先保证右上角关闭按钮和 `拍照 / 选图识别二维码` 完整可见，可压缩扫码区高度。
- 扫码实现优先使用浏览器原生二维码识别能力，浏览器不支持时再回退到 `jsQR`，避免要求用户长时间固定镜头。

不可擅自变更：

- 扫码成功后应回填会议号和二维码中附带的密码，而不是直接跳过查会流程。
- 在不支持实时扫码的环境下，必须保留图片识别降级路径。
- 分享出来的会议二维码应使用深色码点 + 浅色底色的标准二维码视觉，优先保证扫码识别速度，不使用透明反色二维码作为默认分享码。

### 页面 8：入会预览

- 页面标题按入口来源显示：
  - `预定会议`
- 核心区块顺序：
  - 本地预览舞台
  - 会议号与环境状态标签
  - 摄像头偏好
  - 麦克风偏好
  - 会议主题 / 密码状态 / 入会前检查
  - `进入会议`
  - `返回修改入会信息`

手机与 iPad 差异：

- 手机：本地预览与设置区纵向排列。
- iPad：本地预览在左，偏好和检查卡在右，形成 `2` 列布局。

不可擅自变更：

- 预定会议必须保留入会预览；从加入会议页验证会议号进入时直接进入会议，不经过此页面。
- 不显示额外的 `Preview` 英文眉题，顶部只保留一行页面标题。
- `进入会议` 仍然是蓝色主按钮。
- `快速会议` 不使用这个页面。

## 5. 进入会议后的首屏

### 顶栏

- 左到右顺序：
  - 会议主题
  - 会议号、持续时长与网络状态
  - `结束` 或 `离开`

不可擅自变更：

- `H5` 顶栏不保留桌面端的“主持人工具 / 会议工具 / 全屏”横向按钮组。
- 分享、权限、白板、录制、重连等低频能力必须收纳到 `更多` 底部抽屉中，不再挤占首屏顶栏。
- 主持人和普通参会者的高风险动作必须区分：主持人为 `结束`，其他身份为 `离开`。

### 主舞台

- 两种状态：
  - `主画面`
  - `头像墙`
- 主画面优先展示当前聚焦发言者或共享内容。
- 无主视频时使用头像墙，不显示空白黑屏。
- 主舞台支持双击进入或退出全屏。
- 主舞台内需要明确发言状态，当前发言者使用低干扰绿色边框或标签提示。
- H5 移动端进入会议后必须保持单页显示，主舞台需要填满顶栏和底部工具栏之间的可用空间，不展示默认聊天区或成员缩略条。

### 全屏

- 入口：
  - `更多` 抽屉中的 `进入全屏`
  - 双击主舞台画面
- 退出：
  - 双击全屏画面
  - 后续正式实现可补充系统返回手势或浏览器全屏退出事件监听
- 全屏默认只显示会议画面。
- 全屏后单击会议画面可以显示或隐藏底部工具栏。
- 全屏后必须保持单页显示，不得出现页面级滚动条。
- 进入全屏后必须隐藏：
  - 顶栏
  - 聊天、成员、更多、邀请等所有面板
- 进入全屏时必须自动关闭当前已打开的抽屉或浮层。
- 全屏态默认隐藏底部工具栏，单击后以半透明悬浮条显示，再次单击隐藏。
- 全屏态下除单击唤起的底部工具栏外，不展示开发说明、状态角标或额外工具提示，避免遮挡会议画面。

### 聊天窗口

- 默认状态：进入会议后隐藏，不占用首屏空间。
- 打开方式：点击底部工具栏 `聊天`。
- 位置：以底部工具栏上沿为锚点，贴着底部工具栏上方弹出，不得出现在屏幕中央。
- 内容：
  - 聊天标题与消息数量
  - 最新聊天消息
  - 系统权限申请消息
  - 输入框与发送按钮
- 聊天消息按时间正序展示，最新消息在最下方。
- 关闭后必须回到单页会议画面，不保留聊天占位区域。

### 成员列表

- 默认状态：进入会议后隐藏，不占用首屏空间。
- 打开方式：点击底部工具栏 `成员`。
- 位置：以底部工具栏上沿为锚点，贴着底部工具栏上方弹出，不得出现在屏幕中央。
- 内容：
  - 昵称
  - 角色
  - 当前媒体状态
- 关闭后必须回到单页会议画面，不保留成员占位区域。

### 底部工具栏

- 工具顺序：
  - `静音 / 解除静音`
  - `关闭视频 / 开启视频`
  - `聊天`
  - `成员`
  - `更多`

不可擅自变更：

- 手机首屏底部工具栏固定为 `5` 个主入口，不能回退为横向滚动的 `9` 个按钮。
- 底部工具栏按钮必须按屏幕宽度动态收缩，使用 `5` 等分布局和 `clamp()` 控制图标、字号、间距和按钮高度，不得设置会导致窄屏重叠的固定最小宽度。
- `聊天` 和 `成员` 点击后打开贴近底部工具栏的底部抽屉，默认均不占用首屏。
- `更多` 承载低频能力，但不能删除这些能力。

### 更多抽屉

- 菜单项顺序：
  - `邀请`
  - `共享屏幕`
  - `录制与纪要`
  - `白板`
  - `权限与角色`
  - `进入全屏`
  - `重连信令`
  - `结束会议` 或 `离开会议`

不可擅自变更：

- `进入全屏` 必须在更多抽屉中可见，同时保留双击主舞台的快捷方式。
- `结束会议` 或 `离开会议` 必须使用危险色，与普通工具项区分。

## 6. 会中面板策略

### 手机

- 成员：底部抽屉
- 聊天：默认隐藏，点击后在底部工具栏上方贴附弹出
- 更多：底部抽屉
- 邀请：由更多抽屉打开的底部抽屉
- 结束会议：独立贴附确认面板

### iPad

- 成员：底部工具栏上方贴附浮层
- 聊天：默认隐藏，点击后在底部工具栏上方贴附弹出
- 更多：底部贴附面板
- 邀请：底部贴附面板
- 结束会议：底部贴附确认面板

## 7. 状态要求

### 加载态

- 登录发码中：按钮进入 `loading`，输入区不跳布局。
- 验证会议号中：主按钮进入 `loading`，卡片内容不闪烁。
- 入会中：密码确认层保持可见，主按钮进入 `loading`。

### 空态

- 无活动视频时，必须进入头像墙而不是空白黑屏。
- 无聊天记录时，聊天窗口显示轻量空态说明。
- 无法实时扫码时，扫码层内展示降级提示，而不是直接关掉扫码能力。
- 全屏态无活动视频时，头像墙必须撑满画面，不显示顶栏、工具栏或空白容器。

### 错误态

- 登录失败、会议号无效、密码错误都必须在当前壳层内就地展示。
- 媒体能力不可用时，要在当前页面内展示降级说明，不改变主流程结构。
- 浏览器不支持标准全屏能力时，仍然需要提供页面内沉浸式全屏视觉态，并保留双击切换。

## 8. 一致性规则

- 深色背景、聚光灯效果、蓝色主按钮、圆角玻璃面板、图标粗细必须与 `PC` 预览一致。
- `H5` 端不得额外引入新的品牌色或卡通化视觉。
- `H5` 端不得擅自减少关键能力入口，只能重排位置和层级。
- 设计稿中的菜单名称、按钮名称和关键状态文案必须与当前实现保持一致。
- 会中移动端实现必须优先还原 `docs/design/h5-room-preview.html`，不得在正式实现时擅自增删底部主入口、更多抽屉菜单或全屏触发方式。
