# H5 UI 规格

- 状态：implemented
- 范围：`H5` 浏览器端从登录到进入会议，以及当前已落地的会中单屏壳层
- 对应预览：
  - `docs/design/h5-auth-preview.html`
  - `docs/design/h5-room-preview.html`

## 1. 目标

- 以 `web/src/App.tsx` 当前实现为准，同步维护 `H5` 的 HTML/CSS 设计稿和结构化 UI 规格。
- 继续沿用 `PC Web` 的深色舞台、`meeting` 字标、底部聚光灯、蓝色主按钮和玻璃感面板。
- `H5` 不是把 `PC` 页面等比压缩，而是基于同一视觉系统重排触控优先级、表单密度和会中工具布局。

## 2. 设备分档

### 手机主档

- 基准宽度：`390px` 左右竖屏。
- 交互原则：单列、拇指优先、底部操作区优先。
- 面板策略：`sheet` / 底部抽屉优先。

### iPad / 小屏平板档

- 基准宽度：`820px` 左右竖屏。
- 交互原则：保留 `H5` 壳层，但允许局部双列和右侧贴附面板。
- 面板策略：聊天、成员和应用面板切换为右侧浮层；底部工具栏仍保留会中主操作。

## 3. 全局角标

- 登录页、登录后入口、加入会议、入会预览和会中页左下角都要固定显示版本信息角标。
- 角标固定为 `3` 行，顺序不可擅自调整：
  - `version`
  - `commit`
  - `build time`
- 角标必须使用低对比灰色，不参与主要交互，不得抢占按钮层级，也不应成为页面视觉焦点。

## 4. 登录到入会流程

### 页面 1：登录

- 顶部品牌区顺序：
  - `meeting`
  - 聚光灯
  - 副文案
  - 品牌标签
- 主卡片内容：
  - 登录方式标题
  - `使用验证码登录 > / 使用密码登录 >`
  - `没有账号？去注册 >`
  - 邮箱输入
  - 验证码输入或密码输入
  - `忘记密码`
  - `登录`
  - `微信快捷登录`
  - `加入会议`

不可擅自变更：

- `meeting` 字标和聚光灯必须保留在品牌区。
- `加入会议` 仍然需要在登录卡片内直接可达，不能藏入二级菜单。
- 微信登录在当前实现中是独立图标按钮，设计稿不得改成另一套主流程。

### 页面 2：注册

- 字段顺序：
  - 邮箱
  - 昵称
  - 验证码
- 主操作顺序：
  - `注册`
  - `加入会议`
- 次级入口：
  - `已有账号？去登录 >`

不可擅自变更：

- 注册完成后返回登录页重新登录的流程语义必须保留。

### 页面 3：登录后入口

- 卡片顺序：
  - `快速会议`
  - `预定会议`
- 辅助入口：
  - `已有会议号？加入会议`
- 最近会议摘要：
  - 会议号
  - 主题
  - 时间
  - 是否需要密码

手机与 iPad 差异：

- 手机：能力卡纵向堆叠。
- iPad：能力卡允许双列并排。

### 页面 4：预定会议

- 表单字段顺序：
  - `会议主题`
  - `会议时间`
  - `时区`
  - `会议密码（可选）`
- 底部按钮顺序：
  - `预定并进入预览`
  - `返回`

实现说明：

- 当前后端还没有真正的预约会议模型，本轮预定表单会创建可立即进入的会议，然后跳入会预览。

### 页面 5：加入会议

- 字段顺序：
  - `会议号 / Meeting ID`
  - `昵称`
- 会议号输入区形态：
  - 输入框
  - 右侧内嵌 `扫码` 按钮
- 入会偏好顺序：
  - `入会时希望开启摄像头`
  - `入会时希望开启麦克风`
- 底部按钮顺序：
  - `验证会议号`
  - `返回`

不可擅自变更：

- 会议号仍然使用公开 `9` 位数字并按 `3-3-3` 展示。
- 仍然是“先验证会议号，再决定是否弹出密码确认”。

### 页面 6：密码确认

- 手机端形态：固定悬浮窗 / 遮罩层中的卡片。
- iPad 端形态：同一层级的居中浮层。
- 信息顺序：
  - 已确认会议号
  - 标题 `请输入会议密码`
  - 密码输入框
  - `加入并进入预览`
  - `返回`

### 页面 7：扫码加入会议

- 入口位置：加入会议页会议号输入框右侧。
- 弹层顺序：
  - 标题 `扫码加入会议`
  - 状态说明
  - 实时扫码区或降级占位区
  - 状态文案
  - `拍照 / 选图识别二维码`
  - `关闭扫码，改为手动输入`

不可擅自变更：

- 扫码成功后应回填会议号和二维码中附带的密码，而不是直接跳过查会流程。
- 在不支持实时扫码的环境下，必须保留图片识别降级路径。

### 页面 8：入会预览

- 核心区块顺序：
  - 本地预览舞台
  - 会议号与环境状态标签
  - 摄像头偏好
  - 麦克风偏好
  - 会议主题 / 密码状态 / 入会前检查
  - `进入会议`
  - `返回修改入会信息`

手机与 iPad 差异：

- 手机：本地预览与设置区纵向排列。
- iPad：本地预览在左，偏好和检查卡在右，形成 `2` 列布局。

不可擅自变更：

- 入会预览必须保留在正式进入会议之前。
- `进入会议` 仍然是蓝色主按钮。

## 5. 进入会议后的首屏

### 顶栏

- 左到右顺序：
  - 返回
  - 会议详情
  - 持续时长
  - 网络状态入口
  - 分享

### 主舞台

- 两种状态：
  - `主画面`
  - `头像墙`
- 主画面优先展示当前聚焦发言者或共享内容。
- 无主视频时使用头像墙，不显示空白黑屏。

### 参会者缩略条

- 位置：主舞台下方、底部工具栏上方。
- 内容：
  - 头像
  - 昵称
  - 当前媒体状态

### 底部工具栏

- 工具顺序：
  - `静音 / 解除静音`
  - `关闭视频 / 开启视频`
  - `共享屏幕`
  - `邀请`
  - `成员`
  - `聊天`
  - `录制 / 停止录制`
  - `应用`
  - `结束会议` 或 `离开会议`

不可擅自变更：

- 主持人和普通参会者的最后一个高风险动作必须区分：主持人为 `结束会议`，其他身份为 `离开会议`。
- `应用` 入口必须独立保留，不能并回聊天或成员面板。

## 6. 会中面板策略

### 手机

- 成员：底部抽屉
- 聊天：底部抽屉
- 应用：底部贴附面板
- 邀请：独立弹窗
- 结束会议：独立贴附确认面板

### iPad

- 成员：右侧浮层
- 聊天：右侧浮层
- 应用：底部贴附面板
- 邀请：独立弹窗
- 结束会议：底部贴附确认面板

## 6. 状态要求

### 加载态

- 登录发码中：按钮进入 `loading`，输入区不跳布局。
- 验证会议号中：主按钮进入 `loading`，卡片内容不闪烁。
- 入会中：密码确认层保持可见，主按钮进入 `loading`。

### 空态

- 无活动视频时，必须进入头像墙而不是空白黑屏。
- 无聊天记录时，聊天面板显示轻量空态说明。
- 无法实时扫码时，扫码层内展示降级提示，而不是直接关掉扫码能力。

### 错误态

- 登录失败、会议号无效、密码错误都必须在当前壳层内就地展示。
- 媒体能力不可用时，要在当前页面内展示降级说明，不改变主流程结构。

## 7. 一致性规则

- 深色背景、聚光灯效果、蓝色主按钮、圆角玻璃面板、图标粗细必须与 `PC` 预览一致。
- `H5` 端不得额外引入新的品牌色或卡通化视觉。
- `H5` 端不得擅自减少关键能力入口，只能重排位置和层级。
- 设计稿中的菜单名称、按钮名称和关键状态文案必须与当前实现保持一致。
