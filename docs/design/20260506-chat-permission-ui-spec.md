# 2026-05-06 聊天未读与权限处理 UI 规格

## 背景

生产环境反馈显示，匿名参会者发起麦克风权限申请后，主持人侧聊天入口缺少未读提示，聊天抽屉内消息排序和视觉密度不符合即时通讯预期，且“快速处理 / 主持人授权 / 设为助理”缺少明确操作反馈。

## 目标

- 聊天入口在聊天抽屉关闭时显示未读数量，打开聊天后自动清零。
- 聊天消息按时间从上到下排列，最新消息固定出现在最下方。
- 聊天消息采用紧凑消息流样式，普通消息不再渲染成大卡片。
- 权限申请系统消息保留轻量高亮和“点此快速处理”入口。
- 主持人授权和设为助理使用参会者下拉选择，避免手填 `participantId`。
- 点击“主持人授权”或“设为助理”后必须有可见反馈；信令未连接或服务端拒绝时必须显示错误。

## 非目标

- 不调整后端权限模型和信令协议语义。
- 不新增新的会中通知中心。
- 不改变移动端和微信小程序的聊天壳层结构。

## 结构与交互

- 底部工具栏保留原有工具数量和顺序：麦克风、摄像头、共享屏幕、邀请、成员、聊天、录制、应用入口。
- 聊天按钮右上角显示红色未读徽标，仅在聊天抽屉关闭且有新消息时出现。
- 聊天抽屉标题右侧仍显示总消息数，打开抽屉时未读数清零。
- 聊天列表使用纵向消息流，普通消息只有分隔线，不使用独立卡片背景。
- 系统权限申请消息使用轻量边框和背景高亮，保留“权限申请”标签和“点此快速处理”入口。
- 点击“点此快速处理”后打开“权限与角色”弹窗，并预填申请人和申请能力。
- “授权目标”和“助理目标”均为参会者下拉框，选项格式为“昵称 · 角色 · participantId 前 8 位”。
- 未选择目标时，“主持人授权”和“设为助理”按钮不可用。
- 操作成功发出后，在弹窗内显示绿色反馈；服务端返回错误时显示红色错误反馈。

## 状态

- 空态：聊天列表显示“当前还没有聊天消息。”
- 加载态：沿用现有会中连接状态，不新增聊天加载态。
- 错误态：信令未连接、发送失败或服务端拒绝时，在权限弹窗内显示错误文案。
- 响应式：桌面端优先修复；移动端继承消息流样式，不改变抽屉触发入口和工具栏顺序。

## 实现核对清单

- 聊天列表不得再调用反向渲染逻辑。
- 新消息到达且聊天抽屉关闭时，未读数递增。
- 聊天抽屉打开时，未读数清零并滚动到底部。
- 快速处理打开权限弹窗后，目标和能力必须已预填。
- 授权和设助理操作不得使用静默可选调用吞掉失败。
- `CHANGELOG.md` 必须记录本次用户可感知修复。
