# 20260518 AI 会议记录与纪要持久化方案

- Status: implemented
- Date: 2026-05-18

## 背景与问题定义

当前 `Meeting` 已支持会中临时纪要、聊天、白板、就位确认和本地录音/录屏，但仍遵循两个核心边界：

- 音视频媒体面保持 `WebRTC Mesh`，服务端不参与媒体转发。
- 会议正文运行态随会议结束清理，服务端只持久化审计和统计数据。

现在需要新增“会议记录与会议总结”能力，目标流程变为：

1. 会议过程中，各参会端上传自己的麦克风音频片段。
2. 后端通过非 LLM 的语音转文字能力实时生成会议发言记录。
3. 会议结束时，只有主持人可以主动点击“AI 整理会议纪要”。
4. 主持人确认后可以立即关闭会议；后端继续静默完成 LLM 纪要整理。
5. 纪要生成后邮件发送，并持久化到服务器。
6. 注册用户可以查看自己的参会记录；主持人可以把纪要分享给其他注册参会用户。

这会突破原先“会议正文不持久化”的边界，因此需要独立方案约束权限、隐私、数据生命周期、后台任务和存储模型。

## 目标与非目标

### 目标

- 在不改变现有 `P2P WebRTC` 媒体拓扑的前提下，接入实时语音转文字。
- 采用“各参会端上传自己麦克风音频片段”的采集方案，避免主持人混音后无法区分发言人。
- 会议过程中只做 ASR 转写，不调用 LLM 做总结、改写或翻译。
- AI 整理纪要必须由主持人主动点击触发，不能自动触发。
- 主持人触发 AI 整理后允许立即结束会议，后台任务继续生成纪要。
- 会议纪要生成后通过邮件发送，并在服务器持久化。
- 注册用户可查看自己的历史参会记录。
- 主持人可将会议纪要分享给其他注册参会用户。

### 非目标

- 本轮不处理微信小程序端。
- 本轮不做同声传译、多语言翻译或双语纪要。
- 本轮不引入 SFU，也不做服务端集中录音。
- 本轮不要求保留原始音频作为长期资产。
- 本轮不让 LLM 直接处理音频；LLM 只处理最终转写文本和结构化会议上下文。
- 本轮不支持匿名参会者会后登录查看纪要；匿名用户必须注册并被主持人分享后才有会后访问入口。

## 术语与核心决策

### 已确认产品决策

- 小程序端不在本轮范围内。
- 会议过程采用 ASR 先实时转写为会议记录，不在会中调用 LLM 做整理。
- 实时记录默认不开启，在工具栏新增“AI 助理”入口。
- “AI 助理”只允许主持人开启；其他参会人员点击时提示“该功能只能主持人开启”。
- 会议结束时，由主持人主动点击并确认是否交由 AI 整理会议纪要。
- 主持人确认后可以立即关闭会议，后端静默完成纪要生成。
- 音频片段不保留，成功转写为文本后立即删除。
- 会议纪要使用 Markdown 纯文本格式持久化保存，不支持主持人删除。
- 纪要生成完成后仅邮件发送给主持人。
- 主持人可以将会议纪要分享给其他注册参会用户。
- LLM provider 使用 DeepSeek V4 系列，默认使用 `deepseek-v4-flash`，并可通过配置切换为 `deepseek-v4-pro` 或其他兼容模型。

### ASR 与 LLM 边界

- `ASR`：语音识别（Automatic Speech Recognition），用于把普通话或英文发言转成文本。
- `LLM`：大语言模型，用于在主持人主动触发后，把转写文本整理为会议纪要。

产品上可以把会中能力称为“实时转写”或“会议记录”，但技术上它仍然依赖语音识别模型。这里的“非 AI 语音转文字”应理解为“不使用 LLM 做语义整理”，而不是完全不使用模型。

### 采集方式

采用客户端分片上传自己麦克风音频：

- 每个参会端只上传自己的麦克风音频，不上传远端混音。
- 每个音频片段带 `participantId`、`userId`、昵称快照、语言、序号和时间戳。
- 后端按参会者归属生成转写段落，避免后处理说话人分离。
- 音频上传使用独立 HTTP 或二进制通道，不复用现有 JSON 信令通道。

### 数据留存

- 原始音频片段只作为临时处理数据，不作为业务资产保存。
- 原始音频片段转写成功后必须立即删除；转写失败时仅允许保留到重试或超时清理边界。
- 最终转写文本、AI 纪要、参会记录和分享关系持久化保存。
- 会议纪要不提供主持人删除能力；后续如需清理只能通过管理员运维策略或合规保留策略处理。
- 会中聊天、白板和就位确认仍保持现有临时模型；如果 AI 整理需要引用这些上下文，应在主持人触发整理时生成一次上下文快照。

### 主持人主动触发

- AI 整理纪要只允许主持人触发。
- 助理默认不能触发，除非后续单独扩展“主持人授权助理整理纪要”。
- 没有主持人点击时，后端不得自动调用 LLM。
- 触发后任务应持久化，会议关闭、信令断开或后端重启后仍可恢复执行。

## 用户流程

### 会中实时记录

1. 会议创建后实时记录默认关闭。
2. 工具栏新增“AI 助理”入口。
3. 主持人点击“AI 助理”后可以开启实时记录。
4. 非主持人点击“AI 助理”时只提示“该功能只能主持人开启”，不得开启录音或上传音频。
5. 主持人开启后，所有参会者界面显示明显的实时记录状态。
6. 参会者开启麦克风后，客户端按片段上传本机麦克风音频。
7. 后端调用 ASR 服务生成转写段落。
8. ASR 成功后写入文本并立即删除对应音频片段。
9. 前端通过 WebSocket 收到 `transcription.segment` 事件，并在“会议记录”面板中实时展示。
10. 参会者离会或关闭麦克风后，对应客户端停止上传音频片段。

### 结束会议与 AI 整理

1. 主持人点击结束会议。
2. 如果会议存在转写内容，结束确认框展示“AI 整理会议纪要”选项或独立按钮。
3. 主持人主动点击并确认后，后端创建纪要生成任务。
4. 前端提示“纪要生成中，完成后会邮件通知”，主持人可以立即关闭会议。
5. 后端等待剩余 ASR 片段完成或超时，然后调用 LLM 生成纪要。
6. 纪要生成成功后：
   - 发送邮件给主持人。
   - 将纪要持久化到服务器。
   - 记录任务状态和生成时间。
7. 主持人可在“我的会议 / 参会记录”中查看历史会议与纪要。
8. 主持人可选择注册参会者并分享纪要；被分享用户可在自己的参会记录中查看。

- `internal/meeting`
  - 扩展会议运行态中的实时记录状态。
  - 提供转写段落追加、读取和会议结束前快照能力。

- `internal/httpapi`
  - 新增音频片段上传接口。
  - 新增纪要任务创建、参会记录查询、纪要查看和分享接口。

- `internal/signaling`
  - 新增转写段落、转写状态、纪要任务状态事件。
  - 不承载音频二进制数据。

- `internal/storage/sqlite`
  - 新增转写、纪要任务、纪要正文和纪要分享表。

- `internal/auth`
  - 复用现有注册用户与会话。
  - 纪要查看和分享必须绑定注册用户身份。

  - 新增“我的参会记录 / 会议纪要详情 / 分享纪要”页面或入口。

- `web/src/api.ts`

### REST API 草案

- `POST /api/meetings/{meetingNumber}/participants/{participantID}/transcription/chunks`
  - 上传当前参会者的麦克风音频片段。
  - 请求可使用 `multipart/form-data`，包含音频文件和 JSON 元数据。

- `GET /api/meetings/{meetingNumber}/transcript?participantId=...`
  - 获取当前会议实时转写快照。

- `POST /api/meetings/{meetingNumber}/minutes/jobs`
  - 主持人主动创建 AI 整理任务。
  - body 包含 `hostParticipantId`。

- `GET /api/meetings/{meetingNumber}/minutes/jobs/{jobID}`
  - 查询纪要生成任务状态。

- `GET /api/users/me/meeting-history`
  - 查询当前注册用户自己的参会记录。

- `GET /api/meeting-minutes/{minutesID}`
  - 查看自己有权限访问的会议纪要。

- `POST /api/meeting-minutes/{minutesID}/shares`
  - 主持人将纪要分享给其他注册参会用户。

- `DELETE /api/meeting-minutes/{minutesID}/shares/{userID}`
  - 主持人取消分享。

### WebSocket 事件草案

- `transcription.status`
  - 广播实时记录开启、关闭、异常等状态。

- `transcription.segment`
  - 广播最终或阶段性转写段落。

- `minutes.job_created`
  - 主持人确认 AI 整理后广播任务已创建。

- `minutes.job_completed`
  - 如果会中仍有人在线，可广播任务完成状态；会后主要依赖邮件和历史记录页查看。

### ASR provider 候选

价格和免费额度变化较快，以下仅作为 2026-05-18 的阶段性选型参考，落地前仍需按 provider 官方价格页复核。

#### 优先候选

- 腾讯云语音识别
  - 适合普通话实时转写和国内网络环境。
  - 有实时语音识别免费额度，支持预付费资源包和后付费。
  - 官方文档要求开通前完成实名认证和人脸认证，个人实名账号可以用于开发和测试；团队或商业业务建议企业实名账号。

- 阿里云智能语音交互
  - 适合国内云资源体系和普通话实时转写。
  - 实时语音识别按处理的语音时长计费，可自助开通后付费商用版。
  - 阿里云支持个人实名认证；团队或商业业务建议企业实名账号。

#### 备选候选

- 科大讯飞开放平台
  - 中文普通话、方言和会议场景经验较强。
  - 新用户通常有试用礼包，正式价格需要在开放平台控制台或购买页确认。

- OpenAI GPT-Realtime-Whisper / Google Cloud Speech-to-Text / Azure AI Speech / Deepgram / xAI Speech to Text
  - 英文和多语言能力较强，部分 provider 提供免费额度或试用金。
  - 对国内部署需要重点评估网络稳定性、付款方式、数据出境和合规要求。

- 自部署 ASR：FunASR、faster-whisper、sherpa-onnx、Vosk
  - 软件本身免费或开源，成本主要是服务器、GPU/CPU、运维和效果调优。
  - 不依赖第三方账号，隐私可控。
  - 需要自行承担实时性、并发、热词、标点、VAD、监控和扩缩容能力。

#### 阶段性建议

第一阶段建议二选一：

- 如果目标是尽快稳定上线中文会议实时记录，优先选腾讯云或阿里云实时 ASR。
- 如果目标是控制现金成本并接受运维复杂度，先自部署 FunASR 或 faster-whisper 做 MVP，再根据效果切换云 ASR。

## 权限与访问控制

### 会中权限

- 实时记录状态对所有会中参会者可见。
- 只有当前参会者本人可以上传自己的音频片段。
- 后端必须校验 `participantID` 属于当前会话或当前匿名参会者。
- 匿名参会者可以参与会中转写，但会后默认没有持久化访问身份。

### AI 整理权限

- 只有主持人可以触发 AI 整理任务。
- AI 整理任务必须幂等：同一会议已有 `pending/running/succeeded` 任务时，重复点击不应创建重复任务。
- 主持人触发后，任务归属到主持人的注册用户 ID。

### 纪要查看权限

- 主持人默认可查看自己主持会议的纪要。
- 被分享的注册参会用户可查看被分享纪要。
- 未注册或匿名用户默认不可查看会后纪要。
- 用户参会记录只展示当前用户主持或以注册身份参加过的会议。

### 分享权限

- 只有纪要所属主持人可以分享或取消分享。
- 分享对象必须是注册用户。
- 第一阶段只允许分享给该会议的注册参会用户，避免主持人误分享给无关用户。

## 后台任务设计

### ASR 任务

- 音频片段上传后进入 ASR 队列。
- ASR 成功后写入 `meeting_transcript_segments`。
- ASR 成功后立即删除对应原始音频片段。
- ASR 失败可按片段重试，超过次数后标记失败并记录日志。
- ASR 失败片段只允许在重试窗口内临时存在，超过重试或超时边界后必须删除。
- 单片段失败不阻断整场会议纪要生成，但需要在任务详情中可观察。

### 纪要生成任务

- 主持人确认后写入 `meeting_minutes_jobs`。
- 后台 worker 扫描 `pending` 和异常中断的 `running` 任务。
- 任务先等待 ASR 队列清空或达到超时时间。
- 然后读取最终转写段落、参会者信息和必要会议上下文，调用 LLM 生成纪要。
- 成功后写入 `meeting_minutes.markdown_content`，更新任务状态，发送邮件。
- 邮件发送失败不应删除已生成纪要；应记录失败并允许后续重试。

### 会议关闭后的处理

- 主持人创建纪要任务后可以立即结束会议。
- 会议内存运行态仍按现有策略清理。
- 转写段落、纪要任务和参会记录已经持久化，不依赖内存会议对象继续存在。
- 如果主持人没有触发 AI 整理，会议结束后不自动调用 LLM。

## 邮件发送

第一阶段默认发送给主持人。

邮件内容建议包含：

- 会议标题
- 会议号
- 会议时间
- 参会人摘要
- Markdown 纪要正文
- 服务器内查看链接

主持人分享给注册参会者时，可发送分享通知邮件。分享邮件不应携带无需登录即可访问的长期公开链接，避免纪要泄露。

## 会议纪要 Markdown 格式

AI 纪要正文采用 Markdown 纯文本格式。LLM 必须基于主持人和其他参会者的发言内容整理目录结构，不输出富文本、HTML 或 provider 私有格式。

建议模板如下：

```markdown
# 会议纪要：<会议标题或会议号>

## 目录

- [一、开场白](#一开场白)
- [二、会议主要议题](#二会议主要议题)
- [三、各议题的讨论](#三各议题的讨论)
```

## 兼容性、迁移方案与风险

### 兼容性

- 现有视频会议、聊天、白板、录制、权限申请和就位确认流程保持不变。
- 小程序端不参与本轮功能，不新增小程序入口。
- 旧会议没有转写和纪要数据，历史记录中可显示为“无会议纪要”。
- 如果 `MEETING_TRANSCRIPTION_ENABLED=false`，前端不展示实时记录入口，后端拒绝音频上传。

### 风险

1. 隐私与合规风险
   - 会议音频、转写文本和纪要都属于会议正文数据，必须明确告知参会者。

2. 成本风险
   - ASR 成本随参会人数和会议时长增长。
   - LLM 成本随转写文本长度增长，需要摘要分块与限流。

3. 准确性风险
   - 标准普通话和英文可作为第一阶段目标，但多人抢话、背景噪声、口音和设备质量仍会影响转写。

4. 数据一致性风险
   - 主持人结束会议时可能仍有音频片段在 ASR 队列中，纪要任务必须处理等待和超时。

5. 安全风险
   - 音频上传接口必须限制大小、频率、会议归属和登录态，避免被当成大文件上传入口滥用。

6. 可恢复性风险
   - 纪要任务需要持久化并支持进程重启后恢复，否则主持人关闭会议后任务可能丢失。

### 迁移策略

- 新增表不改写现有会议运行态表。
- 复用现有 `meeting_usage_meetings` 和 `meeting_usage_participants` 作为参会记录基础。
- 先用 fake ASR / fake LLM provider 打通完整流程，再接真实 provider。
- 先只支持 Web 端，再评估移动 H5 的录音分片兼容性。

## 验证与回滚思路

### 验证

- 单元测试
  - 会议转写段落追加、排序、去重和读取。
  - 主持人触发 AI 整理的权限校验。
  - 纪要任务状态迁移和幂等创建。
  - 纪要分享权限校验。

- HTTP 测试
  - 音频片段上传鉴权、大小限制和错误路径。
  - 参会记录查询只返回当前用户有权访问的数据。
  - 纪要详情与分享接口拒绝无权用户。

- Worker 测试
  - fake ASR 成功、失败、重试。
  - fake LLM 生成纪要成功、失败、超时。
  - 任务在进程重启后可恢复。

- 前端验证
  - 两个 Web 参会端各自上传麦克风片段。
  - 实时记录面板按发言人展示转写文本。
  - 主持人结束会议时主动触发 AI 整理。
  - 主持人关闭会议后仍能收到邮件并在历史记录中查看纪要。
  - 分享后，被分享注册用户能在自己的参会记录中查看纪要。

### 回滚

- 通过 `MEETING_TRANSCRIPTION_ENABLED=false` 关闭音频上传和转写入口。
- 保留已有会议、聊天、白板、录制和临时纪要流程不受影响。
- 若 LLM provider 故障，只影响 AI 整理任务，已生成转写仍可保留。
- 若 ASR provider 故障，可暂停实时记录入口，会议本身继续可用。

## 实施拆分建议

1. 方案与 UI 规格
   - 本方案确认后，补 `docs/design/` 下的 HTML/CSS 设计稿和结构化 UI 规格。

2. 存储与领域模型
   - 新增转写、纪要任务、纪要正文、分享关系表。
   - 扩展查询接口支持我的参会记录。

3. Provider 与后台任务
   - 先实现 fake ASR / fake LLM。
   - 再接真实 ASR / LLM provider。

4. Web 实时转写
   - Web 端采集本机麦克风音频片段并上传。
   - 会中展示实时记录面板。

5. AI 整理与邮件
   - 主持人主动触发任务。
   - 后台生成纪要并发送邮件。

6. 参会记录与分享
   - 注册用户查看历史参会记录。
   - 主持人分享纪要给其他注册参会用户。
