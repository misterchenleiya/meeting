# 会议号对外语义统一第二阶段提案

状态：implemented

## 背景与问题定义

当前系统同时存在两类会议标识：

- 内部会议标识：数据库主键、服务端内存索引、审计事件和日志排查使用，例如 `2bb0271e9826ee3b1f33`。
- 会议号：面向用户展示、复制、分享、扫码和手工输入使用的 9 位数字，例如 `821503974`。

第一阶段已经将 UI、统计邮件和 CSV 报表统一为“会议号”，并要求日志在输出内部 `meetingId` 时同步携带 `meetingNumber`。第二阶段继续把 REST API、WSS 连接路径、前端状态字段和接口文档统一为 `meetingNumber` 语义，避免外部调用方误以为内部长 ID 也是可公开展示的会议号。

## 目标与非目标

目标：

- 对外接口、前端状态和文档统一使用“会议号”语义，避免用户侧再出现内部会议标识。
- 保留内部会议标识作为数据库、审计和日志关联键，不暴露给普通用户界面。
- 日志中只要出现内部 `meetingId`，同一条日志必须包含 `meetingNumber`。
- 保持旧版本客户端在过渡期内可继续通过现有 `meetingId` 路径参数工作。

非目标：

- 不更换数据库主键，不把 9 位会议号改成主键。
- 不迁移历史审计表中的 `meeting_id` 字段。
- 不承诺第三方外部系统立即切换，第二阶段需要提供兼容窗口。

## 方案概述与核心决策

第二阶段采用“外部会议号、内部会议标识”的分层模型：

- 外部输入：REST 路径参数、WSS 路径参数、二维码、邀请链接、前端表单统一命名为 `meetingNumber` 或中文“会议号”。
- 外部输出：面向浏览器 UI 和报表的 DTO 默认返回 `meetingNumber`，不再要求前端使用内部 `id` 建链。
- 内部处理：服务端入口收到 `meetingNumber` 后解析为内部 `meetingId`，业务服务、存储和审计继续使用内部 ID。
- 兼容策略：过渡期内服务端仍接受旧内部 ID 路径参数；信令 Hub 注册房间前会统一归一为内部 ID，避免新旧客户端进入不同房间。

## 涉及模块 / 数据结构 / 接口 / 配置 / 存储影响

- 后端 HTTP API：对外路径参数文档已重命名为 `{meetingNumber}`，服务端继续通过现有 `GetMeeting` 兼容会议号和内部 ID。
- 后端 WSS：连接路径已迁移为 `/ws/meetings/{meetingNumber}`，服务端注册房间前统一解析为内部 ID。
- 前端状态：`JoinFormState.meetingId`、二维码解析结果和运行时 ICE 缓存字段已改名为 `meetingNumber`，旧本地缓存会在读取时兼容迁移。
- DTO：前端普通会议对象优先使用 `meetingNumber`；如确需内部 ID，只保留在调试上下文或服务端日志字段中。
- 统计报表：保持第一阶段结果，继续只展示会议号。
- 存储：无需 schema 变更，`meetings.id` 和审计表 `meeting_id` 保持内部 ID。

## 兼容性、迁移方案与风险

迁移步骤：

1. API/WSS 文档统一切换为显式 `meetingNumber` 路径参数。
2. 前端已改为使用会议号发起查询、加入、信令连接、ICE 凭据获取、审计上报和二维码分享。
3. 服务端继续兼容旧内部 ID 作为路径值，并在信令房间注册和通知广播前归一到内部 ID。
4. 观察至少一个发版周期后，再评估是否彻底移除 API 响应中的内部 `id` 兼容字段。

主要风险：

- 前端如果提前停止携带内部 ID，但后端某个接口仍只接受内部 ID，会导致入会或信令连接失败。
- 第三方或旧客户端如果依赖旧字段名，直接删除会造成兼容性问题。
- 日志字段重命名可能影响既有检索语句，需要在迁移期同时保留 `meetingId` 和 `meetingNumber`。

## 验证与回滚思路

验证：

- 单元测试覆盖会议号查找、内部 ID 查找和不存在标识三种路径。
- 集成测试覆盖创建会议、预定会议入会、匿名入会、WSS 建链、ICE 凭据获取、结束会议和导出纪要。
- 前端构建后检查产物中不再出现面向用户的内部会议标识文案。
- 日志抽样确认所有包含 `meetingId` 的业务日志都同时包含 `meetingNumber`。

回滚：

- 保留旧内部 ID 兼容期间，前端可回滚到继续使用内部 `meeting.id` 作为路径值。
- 数据库不做 schema 迁移，因此服务端回滚不需要数据回滚。
- 若新 DTO 影响旧客户端，可临时恢复同时返回 `id` 与 `meetingNumber` 的兼容输出。
